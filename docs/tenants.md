# 租户与成员

首版提供本地用户名密码登录、租户切换、成员邀请、管理员/成员权限，以及任务、账号池、SkillHub、用量和消息投递的租户范围校验。默认部署仍面向同一受信任组织内的团队；Worker 的文件/Bash 工具使用宿主机账号，目录隔离不等同于操作系统沙箱，不用于承载互不信任的外部企业。飞书 OAuth、组织架构同步、计费及容器级执行隔离未在本版实现。

## 首次登录

打开 `/dashboard.html`，选择“首次设置管理员”，输入本机 `.env` 的 `BUNBIRD_ADMIN_TOKEN`、新用户名和至少 12 位密码。该操作只允许初始化一次；之后使用用户名和密码登录。用户名支持 3–80 位英文字母、数字和 `_.@-`。密码使用独立随机盐及 PBKDF2-HMAC-SHA256（210,000 次）存储。

服务端只保存登录令牌的 SHA-256，8 小时到期。浏览器只在当前页面内存保存令牌，刷新页面后需重新登录；退出会撤销该令牌。登录/邀请码注册按来源地址限制为每分钟 10 次。不使用 Cookie 身份认证；所有受保护请求需要 Bearer 凭据。

已有账号收到新邀请码时，可登录后在“租户与成员”接受邀请，也可在登录页选择“使用邀请码注册或加入”，填写原用户名和密码。后者也支持已被移出所有租户的用户重新加入。错误密码不会消耗邀请码。

## 权限和数据范围

首个账号为平台管理员，可创建租户和登记飞书应用，且自动成为新建租户的管理员。平台管理员通过成员关系进入租户，不提供绕过租户检查的看板查询。租户管理员可以维护本租户的账号、技能、成员和任务；普通成员可查看本租户共享的用量、任务及目录，不能修改。普通成员的只读权限指看板操作，企业内获准使用机器人的飞书用户仍可发送 Agent 任务。

管理员生成的邀请码有效 72 小时、只能使用一次，可指定管理员或成员角色；已加入的用户接受另一邀请码不会改变现有角色。可移除其他成员，不能移除自己。每次请求重新校验成员关系，移除后旧登录令牌不能再访问该租户。首次版本尚无修改密码、密码重置和角色编辑入口。

请求中的 `X-Tenant-ID` 仅用于选择已加入的租户，不能直接授权。后端按凭据建立范围，校验任务详情、事件、取消、账号编辑/模型发现、技能详情/启停。账号 ID 全局唯一，账号状态与额度缓存按该 ID 隔离；环境配置账号仅属于默认租户。其他租户初始没有模型账号或导入技能，必须自行配置后才能执行。SkillHub 本地目录导入仅对平台管理员开放，租户管理员可以导入公开 HTTPS 仓库。

会话、worktree 和附件沿用现有的租户路径隔离；Worker 领取任务时轮询租户，在任务所属租户内选择账号和启用技能，失败切换不会借用别的租户账号。内部 Worker 是平台信任的全局执行器，仍须持有任务租约才能获取凭据或完成任务。同一话题串行执行，每个租户最多 3 个执行中的会话，单个 Worker 总共 3 个执行循环。

## 新增飞书企业

创建租户时将“租户标识”填写为该飞书企业真实的 `tenant_key`，创建后不可修改。平台管理员切换到该租户，填写 `cli_` 开头的 App ID 并保存；看板仅在本次显示生成的 Bridge 连接凭据。应用一旦绑定不可更换，同一应用再次保存会轮换凭据。

为每个企业单独启动 Bridge，在该进程环境配置 `FEISHU_TENANT_KEY`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`BUNBIRD_BRIDGE_TOKEN` 和同一个 `BUNBIRD_CONTROL_URL`。必须使用独立的 `FEISHU_SPOOL_PATH`，如 `data/feishu-team-b.db`，不要让两个 Bridge 共用同一个收件队列。Bridge 与 Worker 的 `ATTACHMENT_ROOT` 必须指向同一存储根，附件目录会继续按 tenant_key 分开。

Bridge 校验飞书事件的企业/应用/发送者，Control 再按该 Bridge 凭据核对企业和应用。不同企业的 Bridge 只能领取自己的消息投递，不能确认其他租户的投递。经校验的飞书发送者记录在 `feishu_identity`，不会仅凭名称或客户端传来的 ID 自动关联到看板账号；本版尚未实现飞书登录关联。

## 现有数据迁移与兼容

V12 增加组织、用户、成员关系、邀请和会话表，账号、技能和投递增加租户字段。服务初始化以现有 `FEISHU_TENANT_KEY` 创建“默认租户”，把旧账号、技能和投递的空租户字段填入该租户。原有任务、Topic、附件已带租户字段，保留原 ID、会话和数据。迁移可重入，只填空字段，不把已归属其他租户的数据迁走。默认飞书应用和 Bridge 凭据仍由原 `.env` 管理。

原 `BUNBIRD_ADMIN_TOKEN` 保留用于首次初始化和既有自动化，只能操作默认租户，不能通过请求头切换租户；创建租户和新增飞书绑定需要已登录的平台管理员。迁移前应停止服务并备份 H2 文件及 `account-vault.key`；回退旧程序时应恢复配套的迁移前备份，不直接把旧版本指向升级后的数据库。

## 验证

`TenantIsolationTest` 覆盖双租户越权、Bridge 身份和投递隔离、租约校验、Worker 账号/技能选择、成员撤销、邀请码一次性、密码哈希和旧数据迁移。`scripts/tenant_smoke.cjs` 对隔离测试服务（18081，空数据库）验证完整网页流程及延迟响应时的租户切换，严禁对真实服务执行该脚本。
